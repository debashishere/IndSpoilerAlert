## What to build

Implement the column mapping and template-saving functionality. When a file is previewed in the UI, the frontend runs fuzzy header similarity matching to automatically suggest mappings for key columns (Product Name, Quantity, Price, Expiry Date). If a mapping is uncertain, the user must be able to change it via dropdown selection elements. When the user confirms, the Express API saves the mapping layout configuration as a `SupplierTemplate` in MongoDB. It then calls the Python sidecar to fuzzy-clean product names (with optional Gemini LLM normalization) and inserts normalized `InventoryLot` records (linking to a created/found `ProductMaster`) with a status of `pending` into MongoDB.

## Acceptance criteria

- [x] Fuzzy matching matches column names (e.g. "QTY (Cases)" $\rightarrow$ `quantity`, "Expiry Date" $\rightarrow$ `expirationDate`) and shows suggested labels in the UI.
- [x] Users can manually select mappings via dropdowns if the system is uncertain.
- [x] Confirming the upload saves the column layout mapping as a `SupplierTemplate` to prevent manual mapping next time.
- [x] Ingested inventory records are successfully saved to MongoDB in the `InventoryLot` collection (and associated `ProductMaster` collection) with `pending` status.
- [x] Product names are normalized (e.g., extracting size units and category markers).
