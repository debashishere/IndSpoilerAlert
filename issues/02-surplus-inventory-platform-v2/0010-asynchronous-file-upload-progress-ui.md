## What to build

Update the file upload flow on the Express API and frontend.
When a user uploads a document, the Express backend should:
1. Save the file to the S3 bucket.
2. Create a `DocumentImport` record with status `'queued'`, `s3Bucket`, and `s3Key`.
3. Push a message to SQS containing the `ingestionJobId` (from MongoDB) and S3 details.
4. Immediately return a `202 Accepted` status to the client with the `ingestionJobId`.

The frontend file upload UI should be updated to receive the job ID, show a processing spinner/progress bar, and poll the job status (via a new status endpoint or websocket) until the status transitions out of `'queued'`/`'parsing'`.

## Acceptance criteria

- [x] `POST /api/ingest/upload` saves the uploaded file to S3 instead of local disk and registers `s3Bucket`/`s3Key` in `DocumentImport`.
- [x] Upload endpoint publishes a job payload to SQS and immediately returns HTTP 202 with `ingestionJobId`.
- [x] A new endpoint `GET /api/ingest/jobs/:id` is added to Express to query a job's current status.
- [x] Frontend upload page handles the HTTP 202 response, triggers a dynamic polling state, and displays progress status updates.
- [x] Integration tests verify S3 storage and SQS publishing under simulated environments.
