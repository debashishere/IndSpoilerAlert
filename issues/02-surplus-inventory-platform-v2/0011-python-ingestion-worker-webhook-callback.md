## What to build

Implement a background worker in the Python sidecar that polls the SQS queue. When a message is received:
1. The worker transitions the import status to `'parsing'` in the database via an Express status update or starts parsing.
2. It downloads the target file from S3 using the S3 client.
3. It runs the Docling table extraction logic on the document.
4. It posts the parsed table grid results (or extraction errors) back to Express via a private webhook endpoint (`POST /api/ingest/callback`).
5. Express updates the `DocumentImport` document to `'parsed'` (with `rawGrid` and suggested mappings) or `'error'`.
6. The Python worker deletes the message from SQS upon successful processing.

## Acceptance criteria

- [x] Python sidecar runs a background SQS polling loop (as a concurrent task/thread or Celery-like structure).
- [x] Worker downloads file from S3, parses PDF/CSV via Docling, and extracts tables.

- [x] On completion, the frontend polling UI updates to show the mapping configuration page populated with the parsed grid.
- [x] Integration tests verify the end-to-end flow from SQS trigger to webhook execution and database update.
