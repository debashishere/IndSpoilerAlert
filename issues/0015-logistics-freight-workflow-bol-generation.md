## What to build

Introduce standard freight coordination and BOL documentation generation:
1. Update `Shipment` status options to `'scheduled' | 'confirmed' | 'in_transit' | 'delivered'`.
2. Add `bolNumber`, `bolPdfUrl`, `carrierName`, `carrierDotNumber`, `pickupWindowStart`, `pickupWindowEnd`, and `temperatureLogs` array to the `Shipment` schema.
3. Automatically generate a Bill of Lading (BOL) PDF using `pdfkit` upon Award creation, capturing carrier, shipper, consignee, and case details. Save it to S3 and record the URL on `Shipment.bolPdfUrl`.
4. Create an Express endpoint `POST /api/shipments/:id/confirm-appointment` to schedule and confirm the dock pickup times. This transitions the shipment status from `'scheduled'` to `'confirmed'`.
5. Enforce that shipments cannot transition to `'in_transit'` unless the status is `'confirmed'`.
6. Update the logistics UI to support scheduling confirmations, show temperature log histories, and link to the BOL PDF download.

## Acceptance criteria

- [ ] `Shipment` schema supports all new carrier details, pickup windows, and temperature logs.
- [ ] BOL PDF is programmatically generated upon award, saved to S3, and mapped to the shipment.
- [ ] API validates that shipment status transitions sequentially (`'scheduled'` -> `'confirmed'` -> `'in_transit'`).
- [ ] Appointment confirmation endpoint `POST /api/shipments/:id/confirm-appointment` is operational.
- [ ] Logistics UI displays the shipment timeline, temperature records, and download links for the BOL PDF.
- [ ] API integration tests verify transition validation rules and BOL document existence.
