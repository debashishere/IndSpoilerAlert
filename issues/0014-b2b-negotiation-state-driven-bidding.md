## What to build

Implement formal bidding state transitions and purchase order generation:
1. Update `Offer` status options to `'pending' | 'countered' | 'rejected' | 'partially_accepted' | 'fully_accepted'`.
2. Unify comments and counter-offers inside the `messages` array, capturing `proposedPrice` and `proposedQuantity`.
3. Support partial awards in the Express `awardBid` logic. When a bid is accepted, the seller can input an `awardedQty`. If `awardedQty` matches the bid quantity, set status to `'fully_accepted'`. If less, set status to `'partially_accepted'`. Deduct `awardedQty` from `InventoryLot`'s `availableQty`.
4. Implement a One-Shot Decision rule: once a bid status is set to `'partially_accepted'` or `'fully_accepted'`, reject any further award attempts against that specific bid.
5. Generate a Purchase Order (PO) PDF using the `pdfkit` library upon award creation. Upload the PO to S3 and save the URL in the `Award` record.
6. Update the bidding UI to allow counter-proposals, display PO document download links, and support partial award inputs.

## Acceptance criteria

- [ ] `Offer` schema status is updated, and the `messages` array acts as the single chronological log for negotiation and counter-offers.
- [ ] `awardBid` service successfully handles partial awards, updates lot `availableQty`, and enforces the One-Shot Decision block.
- [ ] Automatic PO PDF generation triggers upon bid award, saves the PDF file to S3, and records the S3 URL in `Award`.
- [ ] Bidding dashboard UI displays active status states (e.g. countered, partially accepted) and includes a link to download the generated PO PDF.
- [ ] Integration tests verify state changes, database decrements, and PDF file generation.
