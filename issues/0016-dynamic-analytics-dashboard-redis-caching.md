## What to build

Modernize the analytics endpoint to provide real-time reporting with sub-300ms response times:
1. Replace pre-computed analytics snapshots at `GET /api/analytics/summary` with dynamic MongoDB aggregation queries (grouping by category, status, and tracking financial metrics like COGS recovery margins and landfill diversion).
2. Store the resulting JSON in Redis with a 5-minute Time-to-Live (TTL).
3. If Redis is down, capture the error, log a warning, and fall back to running the MongoDB aggregation query directly without throwing a 500 error (fail-safe cache fallback).
4. Update the frontend analytics dashboard charts to query this endpoint dynamically on load.

## Acceptance criteria

- [ ] `GET /api/analytics/summary` executes dynamic MongoDB aggregations instead of reading a static document.
- [ ] Redis cache successfully stores queries and returns cached responses for subsequent requests within the 5-minute TTL.
- [ ] Caching client handles connection failures gracefully, logging warnings and reverting to direct DB querying.
- [ ] Analytics dashboard loads correctly with dynamic data visualizations.
- [ ] Integration tests verify response correctness and ensure Redis fallback logic works as expected.
